# Phase 17 — Admin analytics and reports

Phase 17 adds read-only marketplace reporting to the existing Laravel 13 / PostgreSQL / Inertia / Vue / Wayfinder application. Fortify, Spatie permissions and Phases 1–16 remain authoritative. No package, financial ledger, balance table, account reset, commercial seed or background export job is introduced. Phase 18 is not implemented.

Created:

- `app/Services/Analytics/{ReportFilters,FinancialFacts,AnalyticsReports,MarketplaceAnalytics,ReportCsv}.php`

Modified: `routes/web.php`, `resources/js/components/AppSidebar.vue`, `.env.example`, `config/inertia.php`, generated frontend helpers/build output. Actual `.env`, authentication, domain migrations, financial services, permissions and prior tests are preserved.

`FinancialFacts` defines verified sales, bounded periods, compensation and ledger position queries. `AnalyticsReports` defines report SQL and explicit row/column allow-lists shared with exports. `MarketplaceAnalytics` composes SQL aggregates, comparisons, ranks and charts. `ReportFilters` owns validation and calendar boundaries. `ReportCsv` streams the same query and projection. The controller only validates, invokes services, paginates and renders/downloads.

## Metric glossary and authoritative sources

| Fact                                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Verified paid Order                  | Completed Order with payment status paid, paid timestamp and recorded settled Payment whose status, order, currency and amount match the Order. Payment retries never count as Orders.                                                                                                                                                                                                                               |
| Paid item / unit                     | One immutable purchased OrderItem / its immutable quantity. Current prices and active access do not redefine a historical sale.                                                                                                                                                                                                                                                                                      |
| Gross sales                          | Sum of immutable `order_items.line_total` for verified paid Orders paid inside the selected period. Product/author/origin filters select purchased items, so filtered order totals are the selected items, not unrelated items in the same order.                                                                                                                                                                    |
| Sales-cohort completed refund        | Exact purchased-item Phase 13 compensation belonging to the selected sales cohort, whose Refund is completed before the exclusive reporting end.                                                                                                                                                                                                                                                                     |

Requested, approved, processing, failed and cancelled refunds never reduce this amount.                                                                                                                                                                                                                                                                          |
| Refund activity                      | Sum of exact compensation for Refunds completed inside the selected reporting period, independently of when the original sale occurred.                                                                                                                                                                                                                                                                              |
| Commission earned                    | Original purchased author-sale commission snapshots. Official software creates no fictitious author commission.                                                                                                                                                                                                                                                                                                      |
| Author earned                        | Original purchased author net snapshots, before completed author compensation reversals.                                                                                                                                                                                                                                                                                                                             |

Registration chart uses created date.                                                                                                                                                                                                                                                                                                     |

Authors with paid sales use historical purchased seller identity instead.                                                                                                                                                                                                                                                                                  |
| Public verified review               | Exact Phase 14 `ProductRatingSummary::publicQuery()` qualification, excluding hidden, withdrawn, refunded and otherwise unqualified reviews.                                                                                                                                                                                                                                                                         |
| Item refund rate                     | Completed refunded items in selected sales cohort / selected paid purchased items.                                                                                                                                                                                                                                                                                                                                   |

All money comes from PostgreSQL NUMERIC aggregates and exact decimal strings. Brick Math formats/adds/subtracts/divides only bounded aggregate results; PHP never loads every Order to sum money. No float, FX conversion or current Offer repricing is used. SQLite is a portable test backend, not monetary production authority.

### Sales cohort versus refund activity

An August sale refunded in October appears as October refund activity without appearing as October gross sales. The August report with an August end shows no October compensation; a range including both dates shows the completed cohort adjustment. Cohort measures are explicitly **as of reporting end**, so later refunds do not rewrite an earlier period's retained amount. Original purchased gross remains unchanged. Dashboard cards label both `Sales-cohort refunds` and `Refunds completed in period`; refund charts use completion date.

Refund and payout **report rows** use requested date for date filtering and show their completed/paid dates separately. Dashboard refund activity and paid payout metrics use completion/paid date. An old requested refund completed today may be visible in dashboard activity while absent from a request-date-filtered refund report; this is deliberate and is stated on the report page.

## Currency handling and ranking

INR, USD, EUR and GBP remain separate in financial cards, tables, chart series and CSV columns. Empty marketplaces do not fabricate an INR balance or rating. Gross, refund, retained gross, commission, author earnings, payout, outstanding position and AOV are never combined across currencies.

SQL window ranks partition by currency: five products by retained gross, five by units, five authors by retained sales, five authors by net earned **for each currency**. Monetary product/author report sorting groups currency before ordering values. Public rating ranking is separate and non-monetary. Category/industry performance is labeled per currency. Industry attribution overlaps: one sale can belong to several industries, so industry rows must not be added into marketplace sales.

## Dates, timezone, comparison and charts

`MARKETPLACE_REPORTING_TIMEZONE` / `config('analytics.timezone')` defaults to `Asia/Kolkata`. It is server-controlled; browser timezone input is ignored. Production must configure a valid IANA timezone. Start is inclusive local midnight; end is exclusive local midnight after the last included date. SQL timestamp-with-timezone boundaries include an explicit UTC offset. Naive User registration timestamps are interpreted as application UTC before chart conversion.

Presets: today; last 7/30/90 calendar dates including today; this month/year through today; last complete calendar month; custom inclusive `YYYY-MM-DD` dates. Reversed, malformed or missing custom dates fail validation. Maximum range is 366 calendar days. Comparison uses the immediately preceding equal number of calendar dates, with no overlap. Calendar lengths remain meaningful over DST even if elapsed seconds differ. Gross comparison gives exact absolute/percentage change; previous zero gives null percentage and `New` only if current is nonzero. No infinite percentage or invented growth appears.

Charts aggregate in PostgreSQL and convert using the reporting timezone. Ranges up to 90 days use daily buckets; longer ranges use calendar months. No weekly bucketing is implemented. Incomplete first/last months contain only selected dates. Existing activity series are zero-filled for missing dates; an empty financial period has no invented currency series. Currency and metric selectors show gross, paid orders, completed refund activity, commission and author earnings; registration chart is non-monetary. BigInt handles monetary chart scaling; Number is used only for bounded SVG pixel coordinates. Accessible data lists accompany SVGs.

**Existing environment finding:** application timezone is UTC, while the local PostgreSQL server's default session timezone is Asia/Kolkata and the existing connection does not explicitly override it. Existing timezone-less ORM writes to TIMESTAMPTZ may therefore have been interpreted using the DB session zone. Analytics reads the persisted authoritative instants; it does not reinterpret or rewrite historical commerce. Boundary fixtures explicitly store their intended UTC instant and then test reads with the DB session in Asia/Kolkata. Production should align application/write connection timezone deliberately after reviewing existing timestamps; global timezone changes and historical repair are outside Phase 17.

Controlled reports are sales, products, authors, customers, refunds, payouts, reviews and support. Unsupported names return 404. Existing `/dashboard` remains unchanged. ## CSV security, scale and consistency

All eight reports can export, exceeding the required six. CSV columns are exactly the DTO allow-list; arbitrary fields are ignored. UTF-8 with BOM, RFC-style CSV quoting and explicit empty escape are used. ASCII controls (including TAB/CR/LF) become spaces. A cell beginning with optional whitespace and `=`, `+`, `-` or `@` gets a leading apostrophe. Negative position values are protected as spreadsheet text rather than executable formulas.

Exports fetch 500 rows per chunk, never an unlimited Eloquent collection. Production PostgreSQL owns a **REPEATABLE READ READ ONLY** transaction for the whole stream. The first read establishes one MVCC snapshot; stable ordered OFFSET chunks cannot shift when a new qualifying row commits, or when a concurrent status/amount changes. There are no mutations in the export. Disconnect exits the loop; exceptions roll back and close the stream. Existing test transactions are respected; the independent-process snapshot runner explicitly tests the real no-outer-transaction export path. No file is persisted and no email/download URL is generated.

Long exports hold an MVCC snapshot and may retain dead tuples; keep timeouts/range limits and observe production load. OFFSET cost grows with export depth. At larger scale, a dedicated keyset/server-cursor read or queued authorized export may replace it while preserving consistent snapshot and allow-list contracts. It must not silently fall back to READ COMMITTED offset streaming.

## Privacy and retained boundaries

`reports.view` grants only these facts. No passwords, account email, billing address, license key/hash, artifact disk/path, private download URL, checksum, provider payload, payout destination/encrypted method, private refund reason/admin note, support body/internal note, notification delivery payload or moderation snapshot appears in analytics DTOs/CSV. Report columns are explicit; raw models are never returned. Filter IDs are intentionally minimal admin selection metadata, not commercial secrets. Existing starter-kit shared props still represent the authenticated user's own session; they do not expose a customer/seller profile.

Native Inertia history is encrypted for report/dashboard pages; analytics URLs are excluded from local devtools recording. Existing domain-specific permissions and IDOR checks are unaffected. Domain event listeners/notifications are not invoked by reads. There is no caching or mutable analytics persistence.

## PostgreSQL performance and indexes

Aggregations, verified purchase qualification, grouped compensation and rating subqueries, author positions, distinct cohorts and window ranks happen in SQL. Aggregating compensation before joining items avoids fan-out. Payout product filtering uses EXISTS rather than summing allocated rows. Reports are bounded and exports chunked. Query-count regression confirms dashboard query count remains constant as transactions increase. It does not fetch private artifacts, all release history or full Eloquent Orders.

The snapshot verification runner also executes `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` on financial totals, sales, products/rating, authors, refunds and support aggregates with actual verified purchase/refund fixtures and intact guards. Small-fixture execution was below one millisecond for each query; the product qualified-rating query spent roughly 142 ms planning its inherited eligibility joins. These are correctness/sanity plans, **not production-volume benchmarks**. Existing PK/FK, purchased seller, ledger author/currency/type, refund state/currency/date, payout state/currency/date and support queue indexes are reused. Small-fixture sequential scans are appropriate; no speculative index or migration is added. Reassess paid-date selectivity and eligibility planning with production distribution before adding targeted indexes. No aggressive cache, search engine or competing balance is introduced.

## Production considerations and deferred work

Use explicit business timezone, preserve immutable financial history, keep exports private/no-store, provision least-privilege `reports.view` and maintain normal queue/notification operations. Reporting compares persisted truth; it cannot fix corrupt or misinterpreted historical timestamp/payment records. There is no tax/profit/FX analysis, customer-value scoring, invented SLA, materialized reporting ledger, retrospective email, background export storage or browser tooling dependency. Larger volumes may justify targeted paid-date indexes, reduced eligibility planning costs, searchable facet selectors and cursor exports after measurement. Known unrelated `UserFactory::withTwoFactor()` PHPStan missing return and optional fontaine warning remain. Phase 18 is deferred.
